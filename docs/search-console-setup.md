# Search Console setup

No Search Console verification file or meta tag is in this repository. Live query, impression, and coverage data were not inspected.

## One-time setup

1. Open [Google Search Console](https://search.google.com/search-console) with the Google account that should own `pneuoma.com`.
2. Add the domain property `pneuoma.com`, or the URL-prefix property `https://pneuoma.com/`.
3. Verify with a DNS TXT record at the domain host, or with the HTML file or meta tag method. If a meta tag or HTML file is required, add that exact token in a later change. Do not invent one.
4. Submit `https://pneuoma.com/sitemap.xml`.
5. Leave the existing GA4 tag `G-TQGSNCV7Q2` in place. Link the Search Console property to that GA4 property from the GA4 admin if both accounts are available.

## Monthly review

Do this once a month. Do not publish the numbers on the website.

1. Coverage or Pages report: note excluded URLs, especially duplicates of `/index.html` and soft 404s.
2. Sitemaps: confirm `sitemap.xml` was read and that the URL count is close to the file generated by `npm run sitemap`.
3. Performance: export queries and landing pages for the last 28 days. Separate brand queries (“PNEUOMA”, “Camryn Jackson”) from product queries (games, Classroom Sync, Solfege) and from enterprise queries (custom software, private AI, law firm).
4. Compare landing pages with the intent map in `docs/seo-keyword-map.md`. A query with impressions and no matching page is a candidate for a later page. Do not create a thin page for every variation.
5. URL Inspection: test `/`, `/solutions/private-llm/`, `/platform/games/`, and `/resources/emotional-regulation-games.html` after any release.
6. Core Web Vitals: read the field report if it has data. Do not treat a lab score as field data.

## What this repository cannot do

Search Console data stays in Google. This site does not have a dashboard of rankings, and none should be hardcoded.
